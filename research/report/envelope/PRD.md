# PRD - Envelope 매매 전략 백테스트

## 1. 프로젝트 목적
이동평균선 기반 Envelope(상하단) 채널을 사용한 평균회귀 매매 전략의
파라미터(MA 기간, 이격률 X%) 조합을 그리드 탐색하여 **CAGR을 최대화**하는
조합을 찾는다.

## 2. 해결하려는 문제
- Envelope 채널은 평균회귀 + 추세전환 결합 전략으로 자주 회자되지만,
  KOSPI/KOSDAQ 전체에서 **MA·X% 조합별 실증 성과 비교** 자료가
  본 프로젝트에 부재하다.
- 자의적인 단일 조합(예: MA20 ± 10%) 사용은 과최적화/저성과 위험.
- → 48개 조합을 동일한 포트폴리오 규칙으로 백테스트하여 비교한다.

## 3. 범위 (포함)
- **데이터 소스**: 로컬 PostgreSQL `stocks` 테이블
  (date, open, high, low, close, volume, ticker, name)
- **유니버스**: KOSPI/KOSDAQ 전체 (당일 거래된 종목 모두 포함)
- **백테스트 기간**: 2020-01-01 ~ DB 최종일 (warm-up은 2019-07-01부터 로드)
- **매수 신호**: `close[d] < MA[d] × (1 - X%)` 발생 → 익일 시가 매수
- **매도 신호**: 보유 종목에 한해 `close[d] < MA[d]` 발생 → 익일 시가 매도
  (MA 상향 이력 제약 없음)
- **포트폴리오**: 최대 동시 보유 10종목, 슬롯당 1,000만원, 초기자본 1억원
  - 슬롯이 비면 현금 보유, 신호 발생 시 빈 슬롯에 배정
  - 동일 시점 신호가 빈 슬롯보다 많으면 정렬 키로 선별 (정렬: 이격률
    `(MA - close) / MA` 큰 순서, 동률 시 ticker 오름차순)
- **거래비용**: 매수 수수료 0.015%, 매도 수수료 0.015%, 매도세 0.18%
  (기존 백테스트와 동일)
- **체결 가정**: 익일 시가 체결, 슬리피지 0
- **그리드**: MA ∈ {10, 20, 30, 40, 60, 80, 100, 120}, X% ∈ {5, 10, 15, 20, 25, 30}
  → 48 조합
- **성과 지표**: CAGR(주), 최종자산, MDD, Profit Factor, 거래수, 승률
- **결과 출력**: `results/backtest_envelope.md` (조합별 표 + 상위 5 조합 상세)

## 4. 비범위 (하지 않을 것)
- ETF, 우선주, 스팩 별도 필터링 (현 stocks 테이블 그대로 사용)
- 거래대금/시총 필터, 테마/섹터 필터
- 손절/익절 별도 룰 (오로지 종가<MA 신호로만 청산)
- 분할 매수/매도, 피라미딩
- 외환·해외 종목
- 종목별 상세 차트 생성
- 라이브 트레이딩 자동화 코드

## 5. 사용자 시나리오
1. PO가 `python backtest_envelope.py` 실행.
2. 스크립트가 DB에서 일봉 로드, MA·하단선 사전 계산.
3. 48개 조합을 순회하며 백테스트 → 조합별 메트릭 산출.
4. 결과 표를 `results/backtest_envelope.md`에 저장.
5. PO가 상위 조합을 확인 후 결론을 보고.

## 6. 기능 요구사항
- F1. DB에서 2019-07-01 이후 일봉 데이터를 단일 SELECT로 로드.
- F2. 종목별로 MA(N) 계산 (N: 그리드 내 최대값까지).
- F3. 종목·날짜별로 매수 신호 / 매도 신호 boolean 시리즈 생성.
- F4. 백테스트 엔진:
  - 일자 루프 → 매도 처리 → 매수 처리 → 자본 갱신.
  - 매수 정렬 키: `disparity = (MA - close) / MA` 내림차순.
- F5. 메트릭 계산:
  - 최종자산, 누적수익률, CAGR, MDD, 거래수, 승률, PF.
- F6. 마크다운 리포트 생성.

## 7. 비기능 요구사항
- 단일 머신에서 48 조합 < 30분 실행 (기존 3-bar/MTL 수준).
- 메모리: 4GB 이내.
- 결정적(deterministic) 실행: 동일 입력 → 동일 출력.

## 9. 테스트 관점 핵심 검증 항목
- T1. **MA 계산 정합성**: 직접 계산한 임의 종목의 MA20 vs 함수 출력 일치.
- T2. **하단선 신호 정합성**: 가공한 OHLC 시계열에서
  `close < MA × (1-X%)` 첫 발생일이 함수가 반환하는 buy_signal 첫 True와 일치.
- T3. **매도 신호 정합성**: 보유 중 첫 `close < MA` 발생일이 sell_signal 첫 True와 일치.
- T4. **거래 시뮬 정합성** (소형 시나리오):
  - 종목 1개·기간 30일·MA10·X10 합성 데이터 → 수기 계산한 손익과 엔진 결과 일치.
  - 매수 가격 = 익일 시가, 매도 가격 = 익일 시가, 수수료/세금 정확 반영.
- T5. **포트폴리오 슬롯 제한**:
  - 같은 날 신호 15건 + 빈 슬롯 3개 → 정렬 키 상위 3건만 진입.
- T6. **CAGR 계산 정합성**: 알려진 (시작자본, 종료자본, 기간) 입력 시 공식 일치.

## 10. 제약사항
- pykrx 사용 금지 (서비스 중단/콜랩스).
- 외부 API 호출 금지 (백테스트는 DB 데이터만 사용).
- Python 3.12, pandas, numpy, sqlalchemy, dotenv (기존 환경).
- 모든 문서/주석/리포트 한국어.

## 11. 가정사항
- DB의 `stocks` 테이블은 일자별로 정합성 있는 OHLCV를 보유.
- 액면분할/병합으로 인한 가격 점프는 별도 보정하지 않음 (기존 백테스트와 동일 가정).
- 익일 시가 거래는 모두 체결됨 (유동성 가정).
- 신규 상장/상폐 종목은 데이터 존재 구간에서만 신호 발생.
